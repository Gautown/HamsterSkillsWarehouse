# VitePress config.ts 动态数据注入方案（2026-09-07 实测）

## 问题：config.ts 不能 import node:fs

**症状**：`import { readFileSync } from 'node:fs'` → Rollup `traceVariable` 失败：
```
"readFileSync" is not exported by "__vite-browser-external", imported by ".vitepress/config.ts"
```

**根因**：Vite esbuild 预处理 config.ts 时把 `node:*` 模块 externalize 到 `__vite-browser-external`，Rollup 打包时找不到。

## 解决方案：scan 脚本生成完整 config.ts

`scripts/scan-skills.ts` 扫描完成后，直接写完整 config.ts（含内联 sidebar/nav 数据），**不要 import node 模块**。

### 关键实现细节

1. **defineConfig 导入路径**：必须用 `'vitepress/dist/node/index.js'`
   - `'vitepress'` = client 入口，没有 defineConfig
   - `'vitepress/dist/node/index.js'` = node 入口，有 defineConfig

2. **config.ts 是 scan 脚本生成物**，头部加注释：
   ```
   // AUTO-GENERATED by scripts/scan-skills.ts — DO NOT EDIT
   ```
   手动修改会被下次 scan/build 覆盖。

3. **fsevents Windows 兼容**：config.ts 里 vite.build.rollupOptions.external 加 `['fsevents']`
   ```ts
   vite: {
     build: { rollupOptions: { external: ['fsevents'] } },
     // ...
   }
   ```

## Layout.vue 不 import config.ts

**问题**：`import _config from '../config'` 导致 Rollup 打包 Layout.vue 时尝试 trace config.ts 里的变量 → traceVariable 失败。

**解决**：用 VitePress 内置的 `useData().theme` 读取 themeConfig，用 `useRoute()` 读当前路径。不要 import config.ts。

```ts
import { useData, useRoute } from 'vitepress';
const { theme } = useData();
const route = useRoute();
const navItems = computed(() => (theme.value?.nav ?? []) as NavItem[]);
const sidebarItems = computed(() => (theme.value?.sidebar ?? []) as SidebarItem[]);
```

## theme/index.ts 导出 OfficialLayout

**问题**：删除 `OfficialLayout` export → VitePress 内部 Rollup 找不到组件。

**修复**：保留静态 import + export：
```ts
import OfficialLayout from 'vitepress/dist/client/theme-default/Layout.vue';
export default { Layout, OfficialLayout, enhanceApp(...) };
```
注意：只 import vars.css + fonts.css（不含组件样式），不走官方 extends 主题的全量 theme.css。
